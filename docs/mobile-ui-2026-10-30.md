# 모바일 UI 1단계

## 목표와 완료 조건

shadcn/ui의 Card·Button·Empty·Sheet 구성 방식을 참고해 기존 모바일 홈과 뉴스 필터의 정보 위계, 버튼 역할, 선택 상태를 정리한다. 새 컴포넌트 라이브러리를 추가하지 않고 현재 Pretendard·Lucide·색상 토큰과 네이티브 dialog를 사용한다. 원본 컴포넌트 코드를 복제하지 않는다.

- 320·393·700px에서 홈의 가로 넘침 없이 뉴스 본문 너비를 확보한다. PC 구성과 공통 제목 규격은 유지한다.
- 브리핑 요약 3개와 출처·기준 시각·주의 문구를 그대로 표시하고 전체 보기 링크를 명확히 한다.
- 필터 조건은 적용 전 초안으로 유지한다. 닫기/Escape/배경 클릭은 취소하고 적용·초기화·새로고침·재진입은 기존 의미를 유지한다.
- 선택은 색상과 체크 표시로 구분한다. 필터 선택 영역·버튼은 최소 44px이며 키보드 포커스가 보이고 닫은 뒤 트리거로 돌아온다.
- 빈 검색 결과와 수집 실패·부분 실패·이전 기사 상태를 구분해 표시한다.

## 범위와 데이터 규칙

모바일 홈 CSS, 브리핑 CTA, 뉴스 필터·빈 상태 표현만 바꾼다. API, 정렬·필터링 로직, 저장 키/스키마, 사용자 기록, 금융 값/기간/출처는 바꾸지 않는다. 의존성과 초기 JavaScript 예산을 유지한다.

## 검증

기존 Node 회귀 검사·lint·빌드·초기 JS 예산 검사와 PC/모바일 Chromium 전체 CI를 재사용한다. 홈 UI 검사에 320/393/700px의 필터 적용·취소·초기화·선택 표시·스크롤 가능한 본문·화면 내 푸터·가로 넘침·포커스 복귀와 화면 증거를 추가한다. 중요한 모바일 흐름 변경이므로 구현자와 별도 리뷰를 수행하고 PR에 SHA와 결과를 적는다. 실제 iOS/Safari 검증은 별도로 구분한다.

## 다음 순서

이 단계가 검증된 뒤 Base UI Drawer의 스와이프/스냅 포인트를 평가한다. 입력에는 React Aria를, 중첩 오버레이에는 overlay-kit을 필요에 따라 선택한다. 서로 겹치는 구현을 한꺼번에 설치하지 않는다.
