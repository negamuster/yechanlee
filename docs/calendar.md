# Economic and earnings calendar

The homepage widget sits alongside Maps; Live and Movers occupy the right sidebar. `/calendar` shows the expanded monthly calendar with month navigation. The monthly grid and selected-day list use New York dates; exact release times display in KST by default, with a New York switch. KST dates are printed alongside times to make midnight rollover explicit. Date-only earnings remain US dates; no exact timestamp is fabricated from pre/after-market labels.

Sources (no new API key required):
- NYSE reviewed cash-equity holiday/early-close schedule, generated by exchange_calendars and bundled locally. A separate '거래소' category appears even if provider feeds fail; provider failures remain visible. This uses NYSE as the explicit reference and does not certify real-time trading/halts. See [generation, scope and verification](exchange-calendar.md).
- BLS official ICS: employment, CPI, PPI, JOLTS and other BLS releases.
- BEA official ICS: GDP, personal income/outlays (including PCE) and other BEA releases.
- Federal Reserve official calendar JSON: FOMC, minutes, Beige Book, Board speeches/testimony, conferences and calendar notices. Events coverage is limited to this calendar; federal holidays here do not imply equity market closures.
- Nasdaq earnings calendar: estimated schedules, including pre-market/after-hours/unknown. Dates must be confirmed with company IR. Actual results and consensus figures are not provided in this release.

`GET /api/calendar?from=YYYY-MM-DD&to=YYYY-MM-DD` supports up to seven days. `mode=month` loads up to 31 days of BLS/BEA/Fed schedules without bulk earnings calls; `mode=earnings` loads only the selected US date. Ranges are bounded to 62 days back and 124 days ahead. Monthly dots show known schedule categories; earnings appear after selecting a date. Korean labels and major-release translations are the default, with original titles and an English title option. Same handler runs in Vite and Vercel. Each source is cached for 15 minutes; failures may reuse a successful response up to 24 hours old, explicitly marked stale. BLS additionally falls back to a validated official ICS snapshot, bundled with the deployment and refreshed from this repository when direct access fails. The latest verified snapshot wins. Collection time is preserved in `updatedAt`; snapshots over 48 hours old are marked stale, and those over seven days old are rejected. An unavailable feed is never presented as an empty successful calendar. Failed sources are shown to the user and never interpreted as an empty calendar. The browser refreshes every 15 minutes and updates scheduled-time status every 30 seconds. A passed timestamp is labelled as such, not as confirmation of publication.

`major` is an editorial classification for CPI/PPI/employment/JOLTS/GDP/PCE/FOMC/Beige Book, not a vendor importance score. Coverage does not yet include a complete global economic calendar (e.g. ISM, Census or DOL releases), all company conferences, or Korea releases.

Validation: `node --test tests/calendar.test.mjs`; `npm run build`.

The desktop Live/Movers sidebar is sticky across the dashboard and news column. Its offset follows the measured header height. At widths up to 1000px it returns to normal flow above the articles to avoid covering content.

## BLS collection

`node scripts/refresh-bls-calendar.mjs` fetches the official ICS and atomically replaces `data/bls-calendar.json` only after validating its format and future releases. The GitHub Actions workflow runs every six hours (at minute 23), on collector changes, or manually. A failed fetch leaves the previous snapshot untouched and fails the workflow. GitHub scheduling may be delayed. No API secret is required; repository contents write permission is scoped to the collection workflow. The API reads the raw main-branch snapshot on direct BLS failure so updates do not depend on a new Vercel build. It caches results for 15 minutes and displays the actual collection time for snapshot/stale data.

## FRED fallback for BLS access restrictions

GitHub runners returned HTTP 403 for the BLS ICS even with a descriptive collector User-Agent. The collector now falls back to the St. Louis Fed's public FRED release calendar, explicitly attributed as `FRED (BLS)`. It collects nine release families: CPI, PPI, Employment Situation, JOLTS, Employment Cost Index, Productivity and Costs, State Employment, Metropolitan Employment, and Import/Export Prices. The page states Central Time; IANA America/Chicago rules convert to UTC, then the UI displays KST/ET. Unknown times remain null.

Every selected release page must parse completely, including its published total count, before the FRED snapshot is replaced. Failure keeps the prior snapshot and fails the workflow. FRED updates never change the BLS snapshot's checkedAt. Fresh direct BLS data has priority. When direct access fails, newer FRED schedules replace covered families throughout the collected date range (so removed dates disappear); other BLS releases retain their original verification time and expiry. Each source expires after seven days. A FRED fallback success does not mean BLS direct access is repaired.

## Demand-driven retry and cache boundaries (2026-10-23)

Source failures now have per-instance retry deadlines. HTTP 403 waits 30 minutes, 404/410 six hours, and 429 at least 15 minutes. Transient failures back off from one to 15 minutes; valid Retry-After on 429/503 may extend the wait to 24 hours. Manual refresh does not bypass the deadline. Concurrent requests share the same operation, including BLS/FRED repository snapshot reads; failed snapshot reads are negatively cached. There is no background retry loop.

Every read rechecks the original collection timestamp, even inside a response/snapshot cache window. Failure never renews the 24-hour retained-response or seven-day BLS/FRED snapshot lifetime. Remote snapshots cannot replace a newer verified copy with an older one. Full request/body reads are time-bounded and limited to 2 MiB. Truncated calendar envelopes, unparseable responses and expired data remain unavailable. The existing ICS parser can still omit individual malformed VEVENT entries; this change does not certify complete provider event coverage.

Source metadata adds `checkedAt` (last completed attempt), `error` (sanitized code) and `nextRetryAt`. `updatedAt` remains the original source collection time. Snapshot fallback may be usable while its live-source attempt still reports an error. Such responses are not CDN-cached and remain visible as warnings in the UI and health checker. See [scope and regression criteria](ingestion-reliability.md).
