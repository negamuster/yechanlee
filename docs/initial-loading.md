# 초기 로딩 최적화

목표는 홈의 최신 브리핑을 즉시 표시하면서 과거 브리핑·통합 검색을 사용하기 전에는 관련 데이터와 코드를 내려받지 않는 것이다. 화면 배치와 표시 문단 수, 금융 값·시각·출처·정정·검색 범위·브라우저 저장 형식은 유지한다.

## 로딩 계약과 완료 조건

- `build-briefings.mjs`의 기존 게시 검증을 거친 같은 결과로 전체 아카이브와 최신 한 편을 생성한다. 원본이 없으면 각각 `[]`, `null`이며, 검증 실패 시 빌드도 실패한다. 홈은 최신 한 편을 동기적으로 표시하므로 추가 네트워크 조회나 로딩 깜박임이 없다.
- `briefings.ts`는 최신 한 편·타입·시간 표시를 제공한다. 전체 데이터는 `briefingArchive.ts`에서만 불러오며, 이미 지연 로딩되는 브리핑 페이지와 새로 지연 로딩하는 검색창이 공유한다. 과거 본문의 검색과 출처 링크는 그대로 유지한다.
- 검색창을 처음 열 때 코드·기업 목록·전체 브리핑을 불러온다. 대기 중에도 모달·초점·Esc 닫기·스크롤 복원을 지원한다. 다운로드 실패는 검색 오류로 표시하고 닫기·새로고침 경로를 제공하며 홈 브리핑을 유지한다. 같은 문서에서 실패한 동적 import는 캐시될 수 있으므로 오류 복구는 새로고침을 사용한다.
- 전체 브리핑은 원래 본문·요약·자산·일정·출처·정정을 보존하며 날짜 주소나 `#source-N` 직접 진입도 지원한다. 데이터나 계산·API 할당량에는 변경이 없다.

## 회귀 방지와 측정

Vite 빌드에서 HTML 진입점의 **모든 정적 JavaScript 의존성**을 재귀적으로 합산한다. 동적 import는 사용 전이므로 제외한다. 원본 크기 700,000바이트와 파일별 Node `gzipSync` 기본 압축의 합 210,000바이트를 상한으로 둔다. 전체 브리핑·아카이브 모듈·검색창·SEC 기업 목록이 정적 그래프에 들어오면 크기와 관계없이 실패한다. 경고 한도를 올려 큰 파일을 숨기지 않는다.

기준 main `34631da629df1a09ca5007bdffac2896cfe51708`과 변경 후를 같은 Node 24·lockfile·Vite 8.3.5로 비교했다. 기준도 manifest를 생성해 같은 정적 그래프와 같은 gzip 설정으로 측정했다.

| 최초 JavaScript | 변경 전 | 변경 후 | 감소 |
| --- | ---: | ---: | ---: |
| 압축 전 파일 합 | 944,225 B | 630,894 B | 33.2% |
| 파일별 gzip 합 | 271,713 B | 192,025 B | 29.3% |

이 값은 HTML·CSS·글꼴·이미지·API 응답·YouTube 및 HTTP 헤더를 포함하지 않는 빌드 산출물 비교다. 실제 사용자의 로딩 시간·LCP·INP 개선률을 측정한 값이 아니다. 방문 페이지·캐시·네트워크·압축 방식에 따라 실제 전송량은 달라진다. ECharts는 기존처럼 경제지표 페이지에서 지연 로딩하며 그 페이지의 큰 번들 경고는 남는다. CSS `@theme`/`@tailwind` 경고도 이번 범위에서 수정하지 않는다.

회귀 검사는 최신 자료와 게시 검증 결과의 완전 일치, 최초 홈에서 아카이브·검색 요청 없음, 지연·실패한 검색의 초점/취소/복구, 과거 자료 검색 및 직접 출처 링크를 확인한다. 기존 전체 Node·lint·빌드와 PC/모바일 Chromium 검사를 재사용한다. CI는 `home-ui-review` 아티팩트에 초기 JS 수치도 보관한다. 모바일 검사는 에뮬레이션이며 실기기·Safari 또는 운영 화면 검증은 별도다.
